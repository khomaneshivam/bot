# Execution Architecture, Order State Machine & Reconciliation

## 1. Fail-Closed Execution Contract

In automated trading systems, **broker execution is the single source of truth**. Under no circumstances should an application assume a trade was executed simply because an API function completed or failed with an error.

### 1.1 The Golden Rule of Execution
$$\text{Broker Failure or Timeout} \implies \text{NO INTERNAL OPEN POSITION}$$

When an order submission fails, is rejected, or returns an unacknowledged/ambiguous status:
1. The order state transitions to `REJECTED` or `RECONCILIATION_REQUIRED`.
2. **NO confirmed position is created in `open_positions` or the trading ledger.**
3. If the broker result is unknown (e.g. socket timeout after submission), the reconciliation service is immediately tasked with verifying order existence at the broker before taking action.

## 2. Order State Machine

```
      +-------------+
      |   CREATED   |
      +-------------+
             |
             | Risk Engine Checks Pass
             v
      +---------------+
      | RISK_APPROVED |
      +---------------+
             |
             | Order Routed to Adapter
             v
      +---------------+            Broker Network Timeout
      |   SUBMITTED   | ------------------------------------+
      +---------------+                                     |
             |                                              |
             +-----------------------+                      |
             | Broker Ack            | Broker Reject        |
             v                       v                      v
      +---------------+      +--------------+    +-------------------------+
      | ACKNOWLEDGED  |      |   REJECTED   |    | RECONCILIATION_REQUIRED |
      +---------------+      +--------------+    +-------------------------+
             |                                              |
             | Broker Fill Message                          | Periodic Broker Query
             v                                              v
      +---------------+                         +-----------------------+
      |    FILLED     | <---------------------- | Discovered Real Fill  |
      +---------------+                         +-----------------------+
             |                                              |
             | Close Order / SL / TP                        | Not at Broker
             v                                              v
      +---------------+                         +-----------------------+
      |    CLOSED     |                         |  CANCELLED / ORPHAN   |
      +---------------+                         +-----------------------+
```

### 2.1 State Definitions
- `CREATED`: Order candidate generated by strategy or user.
- `RISK_APPROVED`: Verified against all 9 deterministic risk rules.
- `SUBMITTED`: Dispatched over wire to broker adapter.
- `ACKNOWLEDGED`: Broker confirmed order receipt in matching engine.
- `PARTIALLY_FILLED`: Filled fractionally; balance remains open.
- `FILLED`: Fully executed; confirmed active position now established.
- `REJECTED`: Broker rejected order (insufficient margin, market closed, etc.).
- `CANCELLED`: Cancelled prior to fill.
- `RECONCILIATION_REQUIRED`: Network drop or timeout after submission; requires state audit.

## 3. Automated Broker Reconciliation Engine

The `ReconciliationService` continuously compares internal ledger records against broker tickets:
1. **Internal Positions vs. Broker Positions**:
   - Detects orphan internal positions (internal says open, broker says closed).
   - Detects orphan broker positions (broker has position bot doesn't know about).
   - Detects quantity and direction mismatches.
2. **Execution Timing**:
   - Executed synchronously on application boot before trading starts.
   - Executed on a background 60-second periodic schedule.
   - Executed on-demand immediately following any adapter timeout or reconnect.
